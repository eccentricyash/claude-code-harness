# Accessibility — WCAG 2.2 AA floor

Verified in a real browser, not asserted from source. Claude in Chrome can drive
keyboard navigation and read computed styles; source review alone cannot tell you
whether a focus ring is actually visible over a sticky header.

---

## Contrast — the numbers, stated correctly

A single "4.5:1" is the most common way to get this wrong.

| What | Ratio | Criterion |
|---|---|---|
| Normal text | **4.5:1** | 1.4.3 |
| **Large text** — ≥ 18pt (24px), or ≥ 14pt (18.66px) **bold** | **3:1** | 1.4.3 |
| UI components, form borders, focus indicators, icons carrying meaning | **3:1** | 1.4.11 |
| Disabled controls | exempt | — |
| Logotypes | exempt | — |

**Class:** SEMI — a tool measures the ratio; you decide which text is "large"
and whether a control is genuinely disabled.

**Method:** axe DevTools or Lighthouse, then spot-check placeholder text, muted
captions, and any text over an image or gradient — automated tools frequently
miss those because the background is not a solid computed colour.

## Keyboard — the fastest real test

**Method:** put the mouse down. Tab through the entire flow.

| Check | Expected | Criterion |
|---|---|---|
| Everything interactive is reachable | no keyboard traps | 2.1.1, 2.1.2 |
| Focus is always visible | never `outline: none` without a replacement | 2.4.7 |
| Focus order follows visual order | no jumps caused by DOM order or `tabindex` > 0 | 2.4.3 |
| Escape closes modals; focus returns to the trigger | — | — |
| Focus is trapped **inside** an open modal | — | — |

**Evidence:** the tab order you observed, and where it broke.

### WCAG 2.2 additions people miss

| Criterion | Requirement |
|---|---|
| **2.4.11 Focus Not Obscured** | The focused element must not be hidden behind a sticky header, cookie bar, or chat widget. Very common failure on scroll. |
| **2.5.8 Target Size (Minimum)** | Interactive targets ≥ **24×24 CSS px**, or adequately spaced. Icon-only buttons and table row actions fail this most often. |
| **3.3.8 Accessible Authentication** | Do not require a cognitive test to log in. Allow paste into OTP and password fields; do not block password managers. |

## Semantics and forms

| Check | Expected |
|---|---|
| Landmarks | one `<main>`, plus `<nav>` / `<header>` / `<footer>` |
| Headings | one `<h1>`, no skipped levels |
| Buttons vs links | `<button>` performs an action, `<a href>` navigates. A `<div onClick>` is neither and is invisible to keyboard and screen reader. |
| Images | meaningful ones have `alt`; decorative ones have `alt=""` |
| Inputs | every one has a `<label>` — a placeholder is **not** a label; it disappears on input and usually fails contrast |
| Errors | tied to the field via `aria-describedby`, announced via a live region, and stated in text — never colour alone (1.4.1) |
| Required fields | marked in text or `aria-required`, not by a red asterisk alone |

**Class:** AUTOMATED for most of this — axe catches missing labels, bad heading
order, and missing landmarks reliably.

## Motion

**Requirement:** animations and transitions provide a **reduced-motion
behaviour** when `prefers-reduced-motion: reduce` is set. Reduced or replaced —
not necessarily removed. A fade is usually a fine substitute for a slide.

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

That blanket rule is a floor, not a design. Prefer a considered reduced variant
for anything meaningful.

**Also required:**

- Anything moving, blinking, or auto-updating for more than 5s has a pause control (2.2.2)
- Nothing flashes more than 3 times per second (2.3.1) — this one can cause seizures
- Parallax and scroll-jacking are the usual offenders for vestibular disorders

## Quick pass for a UI change

Six checks, about two minutes:

1. **Tab through it.** Everything reachable, focus always visible?
2. **Zoom to 200%.** Does content reflow, or is it clipped? (1.4.4)
3. **Resize to 320px wide.** Horizontal scrolling? (1.4.10)
4. **Check focus at scroll positions** where a sticky header could cover it.
5. **Measure contrast** on the lowest-contrast text you can find.
6. **Turn on reduced motion** and reload.

**Report what you actually did.** "Reviewed for accessibility" without naming
the checks is not a finding — it is a claim.
